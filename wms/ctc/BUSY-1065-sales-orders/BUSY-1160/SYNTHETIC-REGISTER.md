# Synthetic record register, BUSY-1160

Every record any slice in this plan creates is listed here **as it is created**, before the emit, not
after. A failed emit still leaves a trace.

**Why this file exists, and it is not housekeeping.** These are records with no Cin7 order behind
them, living in `staging-orders-v2`, `staging-shipments` and Manhattan SCALE staging alongside real
CTC data.

**This register is the only thing separating them from real records.** Slice 01 measured that no rule
on `staging-orders-v2-event-bus` filters on `source`, across all 19 rules: routing is on
`detail-type` alone. So an injected event and a real poller event are indistinguishable at the
infrastructure level. They route identically, land in the same tables and reach the same SCALE
staging environment. Nothing downstream can tell them apart except the `QASYN-` reference and this
file.

The account role is `PowerUserAccess` plus `IAMFullAccess`, so permissions are not the constraint
either. The discipline in `CLAUDE.md` is what protects the environment. Treat a missing register row
the way you would treat a missing stage guard on a destructive script.

This epic is already carrying two corrections that came from misreading which order did what. A
synthetic record that is not in this register is indistinguishable from a real one in six weeks.

## Marking rule

* Reference is `QASYN-<seq>-<case>`, for example `QASYN-01-TC6`
* Sequence is a running two-digit number across the whole plan, **never reused**
* **Under 25 characters.** That is the SCALE `ShipmentId` ceiling that hard-errored the 33-character
  split child in BUSY-1159 slices 01 and 07
* The prefix is deliberately not a Cin7 reference shape. Real ones look like `#262208`, `WOR19261`,
  `261115`
* Customer fields are obvious placeholders, never carried from the seed order

## Teardown

Not a default. The cancel path issues a DELETE on the shipment id, so slice 05 can remove these, but
whether to is JJ's call once the DC team starts using Manhattan. **Do not clear this register
silently.** Mark records removed rather than deleting rows.
